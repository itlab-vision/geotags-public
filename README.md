# Проект "Определение локации объекта на основании метаданных фотографии в Exif"

## Краткая информация

**Exchangeable Image File Format (Exif)** - стандарт, который
позволяет добавлять метаданные к цифровым изображениям и медиафайлам.
Примеры метаданных: модель камеры, дата и время съемки, геотеги.
Задача поиска ближайшей локации является основой для решения более
сложных задач (например, навигация).

**Цель проекта** - разработать прототип программной системы,
который решает задачу поиска ближайшей локации.

Подробнее постановка задачи описана
в [презентации](./docs/presentations/MMST-2025.pdf).

Настоящий проект содержит четыре версии программной реализации:

- **Версия 1.0**. Предполагает, что база локаций для поиска хранится
  в формате csv.
- **Версия 2.0**. Предполагает, что база локаций для поиска хранится
  в формате библиотеки FlatBuffers. В процессе работы база десериализуется
  в формат внутренних структур данных проекта.
- **Версия 2.1**. Предполагает, что база локаций для поиска хранится
  в формате библиотеки FlatBuffers. В процессе работы используются внутренние
  структуры FlatBuffers.
- **Версия 3.0**. Предполагает, что база локаций для поиска хранится
  в формате библиотеки FlatBuffers. В процессе работы используются внутренние
  структуры FlatBuffers. Поиск ускоряется за счет предварительного разбиения
  базы локаций на подмножества (сегменты) с использованием равномерной сетки.

## Структура директорий

Репозиторий содержит следующие директории и файлы:

- `3rdparty` - внешние библиотеки и ссылки на внешние зависимости.
- `docs` - руководства по загрузке различных данных,
  промежуточные результаты работы в проекте и презентации
  с семинаров и конференций.
- `include` - заголовочные файлы проекта. Набор файлов разбивается
  на два: `not_fb_structs` содержит заголовочные файлы для реализации,
  которая использует собственные структуры данных для представления
  локации; `fb_structs` содержит заголовочные файлы для реализации,
  которая использует внутренние структуры библиотеки FlatBuffers.
  В корне директории находится объявление структур данных и функций,
  общих для всех версий проекта.
- `src` - файлы исходного кода. Структура директории аналогична
  директории `include`.
- `samples` - примеры использования разработанных библиотек.
- `benchmarks` - скрипты для бенчмаркинга приложений.
- `scripts` - вспомогательные скрипты.
- `tests` - тесты к функциям разработанной библиотеки.
- `CMakeLists.txt` - основной cmake-файл для сборки проекта.
- `README.md` - данный файл.

## Сборка приложения под Linux

Для сборки используется CMake (>=3.24). Внешние зависимости:

1. [TinyEXIF][tinyexif].
1. [OpenCV][opencv].
1. [FlatBuffers v25.2.10][flatbuffers].
1. [Google Test][googletest].
1. [pybind11][pybind11]

Сборка выполнялась под Ubuntu 24.04.

Последовательность сборки вместе с зависимостями следующая:

1. Клонирование репозитория.

   ```bash
   git clone --recursive https://github.com/itlab-vision/geotags
   ```

1. Создание папки для бинарных файлов.

   ```bash
   cd geotags && mkdir build
   ```

1. Конфигурирование. Ниже приведена конфигурационная строка для последующей сборки версии проекта.

   ```bash
   cmake -S . -B build \
         -DBUILD_TINYEXIF=ON -DBUILD_OPENCV=ON \
         -DBUILD_GOOGLETEST=ON -DBUILD_FLATBUFFERS=ON \
         -DBUILD_PYBIND11=ON -DBUILD_PYTHON_BINDINGS=<state> \
         -DBUILD_TESTS=ON \
         -DCMAKE_POLICY_VERSION_MINIMUM=<version> \
         -DUSE_FLATBUFFERS_STRUCTURES=<state>
   ```

    **Примечания:**

   1. Для сборки Python-обертки функции поиска ближайшей локации на основе pybind11
      необходимо указать параметры `-DBUILD_PYBIND11=ON` и `-DBUILD_PYTHON_BINDINGS=ON`.
   1. Для сборки тестов проекта необходимо указать параметр `-DBUILD_TESTS=ON`.
   1. Если библиотеки, от которых зависит проект, уже собраны, то при конфигурировании
      необходимо передать пути до файлов `<package>-config.cmake` так, как показано ниже.

      ```bash
      cmake -S . -B build \
            -DTinyEXIF_DIR=<path_to_TinyEXIF-config.cmake> \
            -Dtinyxml2_DIR=<path_to_tinyxml2-config.cmake> \
            -DOpenCV_DIR=<path_to_OpenCV-config.cmake> \
            -DFlatBuffers_DIR=<path_to_flatbuffers-config.cmake> \
            -DGTest_DIR=<path_to_gtest-config.cmake> \
            -Dpybind11_DIR=<path_to_pybind11-config.cmake> \
            -DBUILD_PYTHON_BINDINGS=<state> \
            -DBUILD_TESTS=<state> \
            -DUSE_FLATBUFFERS_STRUCTURES=<state>
      ```

   Конфигурирование версий проекта 1.0 и 2.0 выполняется с помощью следующей команды:

   ```bash
   cmake -S . -B build \
         -DBUILD_TINYEXIF=ON -DBUILD_OPENCV=ON \
         -DBUILD_GOOGLETEST=ON -DBUILD_FLATBUFFERS=ON \
         -DCMAKE_POLICY_VERSION_MINIMUM=3.5 \
         -DUSE_FLATBUFFERS_STRUCTURES=OFF
   ```

   Конфигурирование версий проекта 2.1 и 3.0 выполняется с помощью следующей команды:

   ```bash
   cmake -S . -B build \
         -DBUILD_TINYEXIF=ON -DBUILD_OPENCV=ON \
         -DBUILD_GOOGLETEST=ON -DBUILD_FLATBUFFERS=ON \
         -DCMAKE_POLICY_VERSION_MINIMUM=3.5 \
         -DUSE_FLATBUFFERS_STRUCTURES=ON
   ```

1. Компиляция.

   ```bash
   cmake --build build
   ```

1. Запуск тестов.

   ```bash
   ./build/run_tests
   ```

## Приложения

Проект включает следующие приложения:

- `./samples/getcoordinates_app.cpp` – приложение для извлечения широты и долготы локации из Exif.
- `./samples/geotags_app.cpp` – приложение для определения текущей локации.
- `./samples/search_districts_app.cpp` – приложение для определения региона (для регионов РФ).
- `./samples/search_admin_unit_app.cpp` – приложение для определения города и региона (для РФ).
- `./samples/cities_grid_app.cpp` – приложение для разбиения базы городов на сегменты.
- `./samples/district_neighbors_app.cpp` – приложения для нахождения соседей регионов (для регионов РФ).
Подробные инструкции по запуску приложений выложены в [документации к приложениям](./samples/README.md).

## Скрипты для бенчмаркинга приложений

Проект включает следующие скрипты для бенчмаркинга приложений:

- `./benchmarks/geotags_app.sh` – автоматический запуск приложения `geotags_app` для сбора статистики
  времени выполнения.
- `./benchmarks/search_district_app.sh` – автоматический запуск приложения `search_district_app`
  для сбора статистики времени выполнения.
- `./benchmarks/calculate_metrics.py` – скрипт для вычисления среднего, минимального и максимального времени
  выполнения каждого этапа работы приложений на основании статистики, собранной с использованием
  одного из предыдущих скриптов.

Подробные инструкции по запуску скриптов выложены в [документации](./benchmarks/README.md).

## Вспомогательные скрипты

Проект включает следующие скрипты для подготовки и предварительной обработки баз данных:

- `./scripts/filter_attractions_table.py` – скрипт фильтрации достопримечательностей городов-миллионников РФ.
- `./scripts/parse_russian_cities_html.py` – скрипт для обработки базы городов РФ.
- `./scripts/parse_world_cities_db.py` – скрипт для обработки базы мировых городов.
- `./scripts/parse_cities_population_1000.py` – скрипт для обработки городов с численностью населения
  более 1000 человек.
- `./scripts/parse_admin_units_db.py` – скрипт для обработки OSM-баз административно-территориальных единиц.
- `./scripts/join_cities_admins.py` – скрипт для объединения базы городов с базами
  административно-территориальных единиц.
- `./scripts/visualize_cities_admins_on_map.py` – скрипт для визуализации на карте баз с городами
  и административно-территориально единицами.

Подробные инструкции по запуску скриптов выложены в [документации](./scripts/README.md).

   - Полная база выгружена с ресурса [World Cities Database][world-cities] и использована
   базовая (Basic) версия, которая является свободно распространяемой
   под лицензией Creative Commons Attribution 4.0.
   - Дата загрузки: 02.05.2025.
   - Далее из нее выделена только интересующая информация с помощью
     скрипта `./scripts/parse_world_cities_db.py`.
1. База данных с городами России.
   - Выгружена с ресурса [Time-In][time-in] c помощью скрипта `./scripts/parse_russian_cities_html.py`.
   - Дата выгрузки: 16.02.2025.
1. База данных городов с населением, превышающим 1000 человек.
   - Выгружена с ресурса
     [Geonames - All Cities with a population > 1000][cities-pop-1000], лицензия CC BY 4.0.
   - Дата загрузки: 03.05.2025.
   - Далее из нее выделена только необходимая информация с использованием скрипта
     `./scripts/parse_cities_population_1000.py`.

## Внешние источники баз достопримечательностей городов-миллионников РФ

Базы достопримечательностей в формате .csv загружены средствами QGIS через плагин
quick-osm.

- Дата загрузки: 01.05.2025.
- Последовательность загрузки описана в
  [`./docs/tutorials/LoadAttactionsDB_OSM.md`](./docs/tutorials/LoadAttactionsDB_OSM.md).
- После загрузки каждая база отфильтрована с использованием скрипта `./scripts/filter_attractions_table.py`.
  В процессе фильтрации удалены ненужные атрибуты в таблицах.

**Примечание:** атрибуты по разным городам-миллионниками отличаются.

   Дата загрузки: 02.09.2025.

Базы выгружены с ресурса [OSM-Boundaries][osm-boundaries]. Подробности о процессе выгрузки

## Сборка базы городов и регионов РФ

Для сборки базы городов и регионов необходимо выполнить следующее:

1. С помощью [вспомогательных скриптов](#вспомогательные-скрипты) подготовить
   базы [данных городов](#внешние-источники-баз-городов-рф-и-мира)
   и [административно-территориальных единиц](#внешние-источники-баз-административно-территориальных-единиц-рф-и-мира).
1. Запустить скрипт `./scripts/join_cities_admins.py`, передав в аргументы базу данных
   городов и базы административно-территориальных единиц. В результате работы скрипта, сформируется
   база, содержащая основные поля базы городов и поля id административно-территориальных единиц
   из переданных баз.
